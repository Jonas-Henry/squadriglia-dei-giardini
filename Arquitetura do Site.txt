Conceito da arquitetura

Quero aproveitar para explicar uma decisão importante.

Você pode estar pensando:

"Por que já criar tantas pastas se muitas ficarão vazias?"

Porque estamos projetando uma aplicação, e não apenas uma página.

Por exemplo:

components → Componentes reutilizáveis (Button, Navbar, Card...)
pages → As páginas da aplicação (Home, About, Contact...)
features → Funcionalidades completas (orçamento, agendamento, dashboard)
services → Comunicação com APIs (EmailJS, futuramente Supabase)
data → Textos estáticos em italiano
constants → Constantes compartilhadas
utils → Funções auxiliares
context → Context API quando precisarmos de estado global

Essa separação deixa o projeto muito mais organizado conforme ele cresce.

components/common → componentes reutilizáveis em toda a aplicação (Button, Card, Input, Modal...).
components/layout → Navbar, Footer, Sidebar.
pages/Home/components → componentes específicos da Home.
pages/About/components → componentes específicos da página Sobre.
